# 가치투자자의 대시보드

미국·한국 주식을 두 가지 방식으로 들여다보는 Flask 웹 대시보드입니다.

- **밸류에이션 지표 탭**: 티커 하나의 최근 3년간 밸류에이션·수익성 지표 13종 추이
- **수익률 비교 탭**: N개 종목의 지정 기간 상대 수익률(기준일=0%)을 한 차트에서 비교

데이터는 [yfinance](https://github.com/ranaroussi/yfinance)(Yahoo Finance)에서 가져오고, 원본 재무 수치를 SQLite에 캐시해 반복 조회 시 네트워크 호출을 최소화합니다.

## 주요 기능

- **티커 조회**: `AAPL`, `MSFT` 등 yfinance가 지원하는 티커를 입력해 조회
- **한글 종목명 · 6자리 코드 자동 변환**: `삼성전자`, `에코프로비엠`처럼 한글로 입력하거나 `005930`처럼 6자리 코드만 입력하면 yfinance 티커(`005930.KS` / `247540.KQ`)로 자동 변환. 코스피는 `.KS`, 코스닥은 `.KQ`를 시장 구분에 따라 자동으로 붙임 (매핑 데이터: FinanceDataReader / KRX)
- **회사명 표시**: 대시보드 상단에 회사명을 표시합니다. 한글 종목은 KRX 상장 목록에서, 해외 종목은 Yahoo Finance(`longName`/`shortName`)에서 가져오며 한 번 확인되면 DB에 영구 캐시됩니다.
- **13가지 밸류에이션·수익성 지표** 시각화
  | 지표 | 의미 | 계산식 |
  |------|------|--------|
  | PER | 주가수익비율 | 시가총액 / 순이익 |
  | PBR | 주가순자산비율 | 시가총액 / 자기자본 |
  | PSR | 주가매출비율 | 시가총액 / 매출 |
  | PEG | PER 대비 이익성장률 | PER / EPS 성장률(%, 1년 전 대비) |
  | EV/EBITDA | 기업가치 / EBITDA | (시총 + 순부채) / EBITDA |
  | Dividend Yield | 배당수익률(%) | 최근 12개월 배당 / 주가 |
  | FCF Yield | 잉여현금흐름 수익률(%) | FCF / 시가총액 |
  | ROE | 자기자본이익률(%) | 순이익 / 자기자본 |
  | ROIC | 투하자본이익률(%) | 세후영업이익(NOPAT) / 투하자본 |
  | 영업이익률 | 영업이익률(%) | 영업이익(EBIT) / 매출액 |
  | 부채비율 (D/E) | 부채비율(%) | 부채(Total Debt) / 자기자본 |
  | 그린블랏 마법공식 | Magic Formula | ROIC + 이익수익률(EBIT/EV, 둘 다 %) |
  | 그레이엄 넘버 | Graham Number | √(22.5 × EPS × BPS) |
- **N개 종목 상대 수익률 비교** (두 번째 탭): 종목 여러 개와 `from`·`to` 기간을 입력하면, 기준일(`from`) 주가를 모두 0%로 맞춘 상대 수익률을 한 차트에 겹쳐 그립니다. 주가의 절대 크기(통화·액면가)는 쓰지 않으므로 원화·달러 종목을 섞어도 그대로 비교됩니다.
  - 배당 재투자·액면분할이 반영된 **수정주가 기준 총수익률**(`history(auto_adjust=True)`)
  - 시장별 휴장일이 다르면 **전체 거래일의 합집합**을 쓰고, 쉬는 종목은 직전 종가를 유지(forward fill)
  - 종목별 색상은 CVD(색각이상) 검증을 통과한 8색 팔레트를 고정 순서로 배정
  - 세로 크로스헤어 + 전 종목 값 툴팁, 기간 요약표(총수익률·CAGR·최대낙폭)
- **오늘 방문자 수** (헤더 우측): 대시보드 페이지를 연 사람 수를 **KST 기준 날짜**로 집계해 조용히 표시합니다. 자세한 동작은 [방문자 집계](#방문자-집계) 참고.
- **의존성 없는 순수 SVG 차트**: 프론트엔드는 외부 라이브러리 없이 바닐라 JS로 라인 차트를 그림
- **SQLite 캐싱**: 원본 재무 수치(raw)만 저장하고 비율은 매번 재계산 → 계산식이 바뀌어도 캐시 재활용 가능
- **TTM 이력 누적**: 분기가 지날 때마다 새로운 TTM(최근 12개월) 스냅샷이 DB에 쌓여, 시간이 지날수록 분기별 이력이 촘촘해짐

## 요구 사항

- Python 3.10+ (개발 환경 기준 3.13)
- 인터넷 연결 (yfinance 최초 조회 시)

## 설치

```bash
git clone <repository-url>
cd valuation-ratio-dashboard

python -m venv .venv
# Windows (PowerShell)
.venv\Scripts\Activate.ps1
# macOS / Linux
source .venv/bin/activate

pip install -r requirements.txt
```

## 실행

### 로컬 개발 (기본)

```bash
python app.py
```

또는 `run.sh`로 띄워도 됩니다(`.venv`의 파이썬을 직접 실행).

```bash
./run.sh
```

- 디버그 모드는 꺼진 상태가 기본입니다.

환경 변수로 동작을 조정할 수 있습니다.

| 변수 | 기본값 | 설명 |
|------|--------|------|
| `HOST` | `127.0.0.1` | 바인딩할 호스트. 로컬 전용이 기본 |

| `FLASK_DEBUG` | `0` | `1`이면 디버그 모드 |

## API

### `GET /api/ratios/<ticker>`

지정한 티커의 비율 이력을 JSON으로 반환합니다. `<ticker>` 자리에는 영문 티커뿐 아니라 **한글 종목명**(`삼성전자`)이나 **6자리 코드**(`005930`)도 넣을 수 있으며, 서버가 yfinance 티커로 변환합니다.

**응답 예시**

```json
{
  "ticker": "005930.KS",
  "display": "삼성전자 (005930)",
  "dates": ["2023-12-31", "2024-12-31", "2025-12-31"],
  "metrics": {
    "PER": [30.9, 9.1, 17.9],
    "PBR": [1.5, 1.0, 1.9],
    "PSR": [1.3, 1.1, 2.2],
    "PEG": [null, 0.4, null],
    "EV_EBITDA": [7.7, 3.3, 7.5],
    "DividendYield": [1.9, 2.7, 1.3],
    "FCFYield": [-3.6, 6.2, 4.1],
    "ROE": [4.1, 8.6, 10.4],
    "ROIC": [2.5, 8.7, 11.0],
    "OperatingMargin": [4.6, 12.8, 16.0],
    "DebtEquity": [3.6, 4.9, 5.9],
    "MagicFormula": [5.6, 22.7, 18.0],
    "GrahamNumber": [56813.2, 91638.2, 98043.7]
  },
  "cache_info": { "annual": "cache", "ttm": "fetched" }
}
```

- `ticker`는 변환된 yfinance 티커, `display`는 사람이 읽기 좋은 이름입니다. 한글 종목은 KRX 상장명, 해외 종목은 Yahoo Finance 회사명(`"Apple Inc. (AAPL)"`)이 자동으로 채워지며, 둘 다 없으면 티커 자체가 들어갑니다.
- 값이 계산 불가(적자, 데이터 부족 등)면 `null`로 반환됩니다. 특히 은행·금융주처럼 손익계산서에 `EBIT`/영업이익 항목이 없는 업종은 `ROIC`, `OperatingMargin`, `MagicFormula`가 구조적으로 `null`이 됩니다(그린블랏 마법공식도 원래 금융주를 제외하고 계산하는 방식이라 자연스러운 결과입니다).
- `cache_info`의 각 값은 `cache`(캐시 사용) / `fetched`(새로 조회) / `cache(stale)`(조회 실패로 오래된 캐시 폴백) 중 하나입니다.
- 종목명이 정확히 일치하지 않으면 `400`과 함께 후보 목록을 담은 `{"error": "..."}`를 반환합니다.

### `GET /api/compare?tickers=&from=&to=`

여러 종목의 기준일 대비 상대 수익률을 반환합니다.

| 파라미터 | 예시 | 설명 |
|----------|------|------|
| `tickers` | `AAPL,MSFT,삼성전자` | 쉼표로 구분, 최대 8개. 한글명·6자리 코드도 가능 |
| `from` | `2023-01-01` | 기준일. 이 날(또는 그 이후 첫 거래일)이 0% |
| `to` | `2024-12-31` | 종료일(포함) |

**응답 예시** (일부 생략)

```json
{
  "start": "2023-01-01",
  "end": "2024-12-31",
  "dates": ["2023-01-02", "2023-01-03", "..."],
  "series": [
    {
      "ticker": "AAPL",
      "display": "Apple Inc. (AAPL)",
      "base_date": "2023-01-03",
      "base_price": 123.4567,
      "prices": [null, 123.4567, "..."],
      "returns": [null, 0.0, "..."],
      "total_return": 102.33,
      "cagr": 42.24,
      "mdd": -16.61
    }
  ],
  "warnings": [],
  "basis": "배당 재투자·액면분할 반영 수정주가(총수익률) 기준"
}
```

- `returns`는 `(주가 / 기준가 - 1) × 100`(%)입니다. 주가의 절대 크기는 비교에 쓰이지 않습니다.
- `dates`는 요청한 모든 종목의 **거래일 합집합**입니다. 어떤 종목이 쉰 날은 직전 종가를 유지하고, 그 종목의 첫 거래일 이전 구간은 `null`로 둡니다(예: 기간 중간에 상장한 종목).
- `base_date`는 종목마다 다를 수 있습니다(`from`이 휴일이거나 상장이 늦은 경우). 각 종목은 자기 `base_date`에서 0%로 출발합니다.
- `cagr`은 기간이 300일 미만이면 `null`(연환산이 무의미한 구간), `mdd`는 기간 내 최대 낙폭(%)입니다.
- 기간에 데이터가 전혀 없는 종목은 `series`에서 빠지고 `warnings`에 사유가 담깁니다. 전 종목이 그렇다면 `400`입니다.
- 주가는 프로세스 메모리에 10분 TTL로만 캐시합니다(재무제표와 달리 매일 바뀌므로 SQLite에 넣지 않음).

## 동작 방식

1. **캐시 확인** — `ratios.get_ratio_history()`가 먼저 SQLite 캐시와 TTL을 확인합니다.
   - 연간 재무제표(annual): 30일 TTL
   - 분기 TTM: 24시간 TTL
   - 스키마 버전(`db.SCHEMA_VERSION`)이 그 티커의 캐시보다 높으면 TTL과 무관하게 강제로 다시 조회 (아래 참고)
2. **필요한 부분만 조회** — TTL이 지난 종류만 yfinance에서 새로 받아 원본 수치를 upsert합니다. 조회에 실패해도 캐시가 있으면 그 값으로 폴백합니다.
3. **비율 재계산** — 캐시된 원본 수치로부터 매번 비율을 계산합니다. 원본만 저장하므로 계산식이 바뀌어도 데이터를 다시 받을 필요가 없습니다.
4. **응답** — 최근 `years`년(기본 3년) 구간만 잘라 프론트엔드로 전달합니다.

### ⚠️ 새 지표를 추가할 때 (개발자 참고)

`ratios.py`의 `RAW_COLUMNS`(`db.py`)에 새 컬럼을 추가해서 지표를 늘렸다면, **`db.py`의 `SCHEMA_VERSION`을 1 증가**시켜야 합니다.

이유: 기존에 캐시된 티커는 새 컬럼이 `NULL`인 채로 남아있는데, TTL이 아직 안 지났으면(연간은 최대 30일) 그 지표가 계속 빈 값으로 표시됩니다. `SCHEMA_VERSION`을 올리면 다음 조회 시 TTL과 무관하게 강제로 한 번 다시 받아와 새 컬럼을 채웁니다. 안 올리면 이미 사용 중인 서버에서는 TTL이 지날 때까지 새 지표가 안 보일 수 있습니다.

### 종목명 변환 (`tickers.py`)

- 입력에 한글이 있거나 6자리 숫자면, KRX 상장 목록에서 코드·시장을 찾아 yfinance 티커로 변환합니다.
- 상장 목록은 FinanceDataReader로 받아 SQLite(`stock_map`)에 캐시하며 **7일 TTL**을 둡니다. 처음 한글 조회가 필요할 때 한 번만 내려받고, 이후에는 네트워크 호출 없이 재사용합니다.
- 한글명은 **정확 일치**를 우선합니다(예: `삼성전자` ≠ `삼성전자우`). 정확히 일치하는 게 없으면 부분일치 후보를 에러 메시지로 안내합니다.

### 방문자 집계

헤더 우측에 "오늘 N명"을 표시합니다. 외부 애널리틱스를 붙이지 않고 SQLite(`visits` 테이블)에만 기록합니다.

- **날짜 기준은 KST 고정**입니다. 서버가 어느 타임존에 있든 `ZoneInfo("Asia/Seoul")`로 날짜를 뽑으므로, UTC 서버에 올려도 한국 시각 자정에 카운터가 바뀝니다.
- **순방문자 기준**입니다. 첫 방문에 랜덤 ID(uuid4)를 쿠키(`vid`, HttpOnly·SameSite=Lax·2년)에 심고 `(날짜, ID)`로 집계하므로, 같은 브라우저로 하루에 여러 번 들어와도 1명입니다(재방문 횟수는 `hits` 컬럼에 쌓입니다).
- **집계는 `/` 렌더링에서만** 합니다. 정적 파일과 `/api/*` 호출은 세지 않으므로, 탭을 옮기거나 종목을 여러 번 조회해도 카운트가 늘지 않습니다.
- **봇은 제외**합니다. User-Agent가 없거나 크롤러·헬스체크·HTTP 클라이언트 패턴에 걸리면 기록도, 쿠키 발급도 하지 않습니다(`app.py`의 `_BOT_RE`).
- **쿠키 값은 형식 검증 후 사용**합니다(32자리 hex). 검증 없이 그대로 키로 쓰면 임의의 쿠키를 보내 `visits` 테이블을 부풀릴 수 있습니다.
- **집계 실패는 페이지를 막지 않습니다.** DB 쓰기가 실패하면 조용히 넘어가고 카운터만 표시되지 않습니다.
- 개인을 식별할 수 있는 값(IP, 접속 이력 등)은 저장하지 않습니다. 남는 것은 랜덤 ID·날짜·횟수뿐입니다.

부하는 무시할 수준입니다. 방문 기록 1건이 약 0.8ms(커넥션 열기 + upsert + commit)로, 캐시가 살아있는 `/api/ratios` 응답(6~13ms)보다 한 자릿수 작고 yfinance 신규 조회(수백 ms~수 초)와는 비교가 안 됩니다. `db.py`가 이미 WAL 모드라 이 쓰기가 읽기를 막지도 않습니다.

### 데이터에 대한 참고

- yfinance 무료 소스는 연간 재무제표 4~5개, 분기 재무제표 4~5개 정도만 제공합니다. 따라서 초기에는 데이터 포인트가 성깁니다.
- 앱을 계속 사용하면 새 분기 TTM 스냅샷이 DB에 누적되어 시간이 지날수록 이력이 촘촘해집니다.
- PEG는 EPS가 역성장하거나 적자인 구간에서는 의미가 없어 `null`로 처리됩니다.
- **투하자본(Invested Capital)**은 yfinance가 제공하는 값(`Total Debt + Stockholders Equity`)을 그대로 사용합니다.
- **세후영업이익(NOPAT)**은 분기별로 세율이 다르므로, TTM 구간은 분기마다 `EBIT × (1 - 그 분기의 실효세율)`을 구해 4개 분기를 합산합니다(EBIT을 먼저 합산한 뒤 평균세율을 곱하는 방식보다 정확함). 실효세율은 `Tax Rate For Calcs`를 우선 쓰고 없으면 `Tax Provision / Pretax Income`으로 계산합니다.
- **두 탭은 주가 기준이 서로 다릅니다.** 지표 탭은 배당 미조정 종가(`auto_adjust=False`), 수익률 비교 탭은 배당 재투자 반영 수정주가(`auto_adjust=True`)를 씁니다. 밸류에이션은 "그날 실제로 얼마였나"를 알아야 하고, 수익률 비교는 "배당까지 포함해 얼마를 벌었나"를 알아야 하기 때문입니다. 그래서 지표 탭 주가와 비교 탭 수익률은 서로 어긋날 수 있습니다.
- **(지표 탭) 주가는 배당 미조정 실제 종가**를 사용합니다(`auto_adjust=False`). yfinance 기본값은 배당까지 소급 차감해서 과거 주가가 실제보다 낮게(고배당주는 -20%대) 나오는데, 그러면 모든 종목이 "과거엔 싸다가 점점 비싸졌다"는 없는 추세를 보입니다. 분할은 소급 조정되며 Yahoo의 주식수도 분할 기준으로 재작성되므로 정합적입니다.
- **EPS는 공시 희석EPS(`Diluted EPS`)를 우선 사용**합니다. `순이익/기말주식수`로 직접 계산하면 우선주가 있는 종목(삼성전자 등)에서 분자는 전사 순이익, 분모는 보통주만이 되어 14%까지 벌어집니다. 공시값이 없는 구간만 직접 계산으로 폴백하며, PEG는 산출 기준이 같은 시점끼리만 비교합니다.
- **자기자본이 0 이하(자본잠식)면** 이를 분모로 쓰는 PBR·ROE·부채비율·그레이엄넘버를 `null`로 둡니다. 그냥 계산하면 고수익 기업인 알트리아(MO, 자기자본 -22억 달러)가 ROE -502%로 표시되는 등 값이 나와도 의미가 없습니다. 그레이엄 넘버는 EPS와 BPS가 *각각* 양수여야 계산합니다(곱만 검사하면 적자+자본잠식 기업이 통과해 우량주보다 높은 값이 나옴).
- **회계연도말과 겹치는 TTM은 만들지 않습니다.** 12월 결산 기업은 TTM 종료일이 연간 결산일과 같아져 `PRIMARY KEY (ticker, date)` 충돌로 감사받은 연간 수치가 4개 분기 단순합으로 덮어써집니다(삼성전자 EBIT 기준 6.6% 차이). 연간 수치를 정본으로 둡니다.
- **재무 항목이 아예 없으면 0이 아니라 `null`** 로 저장합니다. 부채 항목 누락을 '무부채'로 단정하면 부채비율 0%, EV 과소 계상으로 이어집니다.
- **PEG는 이익성장률이 0에 가까우면 값이 매우 커집니다** (AAPL FY2023은 EPS 성장률 +0.33% → PEG 84). 수치상 맞지만 불안정하므로 추이 판단 시 참고만 하세요.

### 알려진 한계 (상위 데이터 소스)

Yahoo의 주식수 기준이 연도별로 바뀌는 종목이 있습니다. 삼성전자는 2024년 5.940B(보통주만) → 2025년 6.630B(우선주 포함)로 잡혀, 실제 유상증자가 없었는데도 시가총액이 약 11.6% 계단식으로 뛰어 PER·PBR·PSR에 실체 없는 굴곡이 생깁니다. 대시보드는 이 값을 그대로 전파하므로, 우선주가 있는 종목의 절대 수준은 참고용으로만 보세요.
